# UX Language Guide

Last reviewed: 2026-06

# Purpose

This document defines how Maintley communicates with users.

It serves as the source of truth for:

* Labels
* Navigation
* Dashboard messaging
* Recommendations
* Maintley Intelligence
* Notifications
* Emails
* Empty states
* Onboarding content

The goal is clarity, familiarity, and actionability.

Users should understand Maintley immediately without learning product-specific terminology.

---

# Language Philosophy

Users should not need to learn Maintley vocabulary.

Whenever possible, use language users already understand.

Prefer familiar terms over internally-created terminology.

Good language feels:

* Familiar
* Practical
* Clear
* Helpful

Poor language feels:

* Corporate
* Technical
* Abstract
* Academic

When choosing between two labels, prefer the one most homeowners would naturally use.

---

# Core Principles

## Use Familiar Language

Prefer words users already know.

Good:

* Property
* Task
* Maintenance
* Service History
* Equipment
* System
* Contractor

Avoid inventing terminology when familiar alternatives exist.

---

## Focus on Action

Language should help users understand what they can do next.

Prefer:

* Add HVAC System
* Complete Task
* Review Recommendations
* Upload Warranty

Avoid:

* Asset Configuration
* Operational Review
* Maintenance Workflow Initiation

Actions should be obvious.

---

## Explain Value

When requesting information, explain why it matters.

Good:

```text id="7s3k6a"
Add Filter Size

Knowing the filter size makes future replacements easier.
```

Better guidance improves completion rates.

---

## Recommend, Don't Judge

Maintley should encourage progress.

Avoid language that implies failure or inadequacy.

Good:

* Add Install Date
* Consider Uploading Warranty Information
* Add Maintenance History

Avoid:

* Property Incomplete
* Missing Critical Documentation
* Documentation Score: 41%

The goal is improvement, not evaluation.

---

* Continuity Risk
* Workflow
* Knowledge Preservation
* Institutional Memory
* Lifecycle Continuity
* Operational Risk
* Asset Intelligence Score
* Property Grade
* Documentation Score

# Dashboard Language

The dashboard should answer:

> What needs my attention right now?

Preferred dashboard sections:

* Action Center
* Needs Attention
* Upcoming
* Recommendations
* Recent Activity

Avoid:

* Property Score
* Property Grade
* Operational Health
* Documentation Score

The dashboard should focus on action rather than evaluation.

---

# Maintley Intelligence Language

Maintley Intelligence should guide users rather than audit them.

Property Scan should be described as an explainable review of saved property records.

Use:

```text
Maintley reviewed what it knows about your property and found a few things worth your attention.
```

Avoid:

```text
AI scanned your house.
```

Property Scan language should emphasize:

* Saved property details
* Systems and equipment records
* Tasks and maintenance history
* A small number of worthwhile next steps

Property Scan language should not imply Maintley inspected the physical property, diagnosed equipment condition, or judged the home.

Good:

```text id="9w5v7r"
Add HVAC Filter Size
```

```text id="yn5x3h"
Record Water Heater Install Date
```

```text id="n5im9l"
Add Recommended Maintenance
```

Avoid:

```text id="u2jl79"
Property Incomplete
```

```text id="7d0rwi"
27 Missing Items
```

```text id="0nwwim"
Documentation Score: 41%
```

Maintley Intelligence should encourage progress.

# Recommendation Writing Guidelines

Recommendations should:

1. Start with an action.
2. Be concise.
3. Explain value when appropriate.

Preferred format:

```text id="fdtuv4"
Add HVAC Filter Size

Knowing the filter size makes future replacements easier.
```

Avoid vague recommendations.

Poor example:

```text id="f2dw4j"
Improve HVAC Information
```

Users should immediately understand what action is being suggested.

---

# Documentation Language

Documentation should remain optional.

Preferred:

* Upload Manual
* Add Warranty Information
* Add Filter Size
* Add Install Date

Avoid:

* Documentation Incomplete
* Missing Required Information
* Incomplete Property Profile

Documentation should improve records without feeling mandatory.

---

# Notification Language

Notifications should be informative rather than alarming.

Good:

* HVAC Filter Replacement Coming Up
* Water Heater Flush Due Soon
* Smoke Detector Check Recommended

Avoid:

* Critical Failure Risk
* Immediate Action Required
* Severe Property Risk

unless a genuinely urgent situation exists.

Notifications should support action without creating unnecessary anxiety.

---

# Email Language

Emails should:

* Be concise
* Focus on action
* Highlight value

Preferred email themes:

* Upcoming maintenance
* Recent activity
* Property Insights
* Recommendations

Avoid excessive urgency.

Users should feel informed rather than pressured.

---

# Tone

Maintley should sound:

* Helpful
* Calm
* Practical
* Clear
* Friendly
* Non-technical

Maintley should not sound:

* Corporate
* Abstract
* Alarmist
* Aggressive
* Overly technical

When in doubt, write as if explaining something to a homeowner standing next to you.

---

# Writing Checklist

Before introducing new user-facing language, ask:

1. Would a homeowner understand this immediately?
2. Is there a simpler word available?
3. Does this help users take action?
4. Does this explain value?
5. Does this avoid unnecessary urgency?
6. Does this feel practical and helpful?

If the answer is no, revise the language.

---

# Guiding Principle

Users should never need to learn Maintley terminology to use Maintley successfully.

The best language is often the simplest language.

Maintley should communicate in a way that feels familiar, practical, and useful while helping users understand what matters, what needs attention, and what action they can take next.
